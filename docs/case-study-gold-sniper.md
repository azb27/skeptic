# Case study: auditing my own XAUUSD system

Generated by `python -m evals.case_study` from `docs/results/case_study_gold_sniper.json`. The harness runs that produced the JSON use private code; the JSON holds aggregates only. Do not edit by hand.

## What was being audited
Gold Sniper v5.3 is a rule-based intraday XAUUSD system I wrote in Pine: ICC phases, fair-value gaps, killzones and multi-timeframe bias, with 1:1 targets. In September 2026 I pre-registered three hypotheses to improve it ([`case_study/PREREGISTRATION.md`](../case_study/PREREGISTRATION.md)) and ran them through a Python re-implementation of the script ([`case_study/RESULTS.md`](../case_study/RESULTS.md)).

That run found **+0.007R per trade before spread and −0.123R at a $0.50 spread** over 2,092 trades on a commercial spot feed. All three hypotheses failed their locked promotion rules, and the system was frozen. The run's own fidelity gate was **unmet**, so those numbers were formally provisional.

## 1. Independent replay on a third feed
Same harness, a different price source: HistData-format XAUUSD 1-minute bid (public HF mirror), New York local time -> UTC, 5m and 1h bars, gold session only, cross-asset scoring off. Cross-asset scoring was off because the container can't reach the data vendor. It is capped at ±0.75 on the score, so it can only move signals near the threshold.

- **The original result reproduces.** On the overlapping period the hit rate is 49.7% (original 49.67%), and net at $0.50 is -0.118R (original −0.123R). - **Two independent engines agree.** Skeptic's bracket engine replayed the harness's signals with its own exit logic and matched the harness's TP1 outcome on 99.7% (5-min) and 99.1% (1-hour) of trades.

## 2. Skeptic's checks on the harness
The harness itself was the strategy: Skeptic called it on truncated and full data, and replayed its signals.

| Check | Result | Evidence |
|---|---|---|
| `future_blind` | PASS | 30 cut points (including 25 at the system's own signal bars), no decision changed |
| `backtest` | REJECT | net -0.1143R per trade, CI [-0.1722, -0.0597], 1,146 trades |
| `costs` | REJECT | gross +0.0137R; break-even spread $0.05 vs $0.50 |
| `random_entry` | REJECT | actual -0.1143R vs random entries with the same stops and timeout -0.1394R (p = 0.21) |
| `stability` | REJECT | 4 of 5 time folds lose money |

- **No look-ahead found.** The first run of the probe did flag the harness, but each "mismatch" was a trade on the final bar that the harness drops because it can't be resolved. That is censoring, not look-ahead; the check was fixed and the fix logged ([`evals/CORRECTIONS.md`](../evals/CORRECTIONS.md) #2).
- **The entries add nothing measurable.** Random entries with the same stops and timeout do about as well. Whatever the rules are detecting, it doesn't survive the exits and the spread.

## 3. The auditor's verdict
Sonnet 5 (effort high) read the write-ups and harness, ran the checks, and returned **REJECT**, class `no_edge`, for $0.05:

> Independent-feed backtest confirms the research team's own honest conclusion: net expectancy at the realistic $0.50 spread is -0.1143R/trade with a 95% CI entirely below zero (-0.172,-0.060), gross edge is only +0.0137R (breakeven spread ~$0.05, far below the real $0.50), random_entry shows the actual entries are statistically indistinguishable from random entries with the same exits (p=0.21), and stability shows 4 of 5 time folds net-losing. future_blind passes (no detectable look-ahead), and the PREREGISTRATION.md/RESULTS.md process is itself sound (correctly froze the strategy after H1-H3 all failed their pre-registered promotion rules). The flaw is simply that the strategy has no directional edge once realistic costs are applied; this is independently reproduced here, not a code or process bug.

## 4. What the auditor missed (my own review of the process)
The auditor judged the research process sound. Reading the two documents against each other, I found three things it should have raised. None changes the conclusion, but an auditor that only confirms the authors is not doing its job:

1. **Out-of-sample discipline isn't recorded.** The pre-registration says the most recent 30% is "not examined until an IS decision is recorded in this file's changelog". The changelog has one entry (the lock), and RESULTS.md reports in-sample and out-of-sample side by side. It didn't matter here, because every hypothesis already failed in-sample, but the rule as written was not followed.
2. **The fidelity gate failed on more than one count.** The gate needs ADX within 0.5 mean absolute error; the harness README reports 0.74 on futures. The results file mentions only the signal-count shortfall (18 of 25 vs ≥ 23).
3. **Two live-trade counts.** The pre-registration cites 25 live trades; the harness README says all 29 live trades were reproduced. Both can be true at different dates, but the record should say which sample the gate was judged on.

This is exactly the failure mode the bench's planned *write-up only* group targets (SPEC §5): research documents that break their own rules. On this case the auditor read the conclusions, not the rules.

## Bottom line
Three feeds, two engines and Skeptic's checks agree. **Gold Sniper v5.3 has no directional edge at this horizon and target geometry; the spread is the whole loss.** The original decision to freeze it stands. What's worth keeping is the process: pre-registration, a stopping rule, clustered uncertainty, and an independent re-run that confirms it.
